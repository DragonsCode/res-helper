# Запуск и эксплуатация

## Разработка

`scripts/setup.sh` воспроизводит установку из lockfiles, применяет Alembic-миграции
и собирает фронтенд. `scripts/dev.sh` запускает оба процесса; выход или остановка
скрипта завершает запущенные им процессы. Не запускайте несколько копий на одних
портах. Для облачных задач используйте существующий checkout: среда уже изолирована.
Не создавайте Git worktree без явного запроса.

Полезные проверки:

```bash
curl --fail http://127.0.0.1:8000/api/health
cd backend
uv run alembic current
uv run alembic check
uv run pytest -q
```

Открытие порта — только проверка запуска. Для функциональной проверки используйте
браузерные сценарии: демо → проект → задача → завершение → перезагрузка страницы.

## Конфигурация

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | SQLAlchemy URL; локально `sqlite:///./.data/research.db` |
| `ALLOWED_ORIGINS` | JSON-массив точных браузерных origin |
| `COOKIE_SECURE` | `true` для HTTPS production |
| `DEMO_ENABLED` | `false` в production; демо создаёт записи в БД |
| `ENVIRONMENT` | `development` или `production` |
| `SESSION_DAYS` | Срок серверной сессии; по умолчанию 7 суток |
| `API_PROXY_TARGET` | Адрес API для Vite development server |
| `PLAYWRIGHT_CHROMIUM_EXECUTABLE` | Необязательный путь к браузеру для E2E |

Production-настройки валидируются: демо выключено, cookie Secure, все разрешённые
origin используют HTTPS. Базу и .env не коммитить. Секреты не требуются для
локального MVP; приложение не обращается к старому NewsAPI.

## Предлагаемая схема развёртывания

1. Статическая React-сборка `frontend/dist` на HTTPS reverse proxy.
2. `/api/*` проксируется к Uvicorn/FastAPI; остальные маршруты SPA возвращают
   `index.html`, кроме существующих статических файлов.
3. PostgreSQL с отдельными учётными данными приложения и резервными копиями.
4. Миграции применяются один раз в release step перед переключением трафика.
5. Реальная origin сайта внесена в `ALLOWED_ORIGINS`.

Не используйте Vite dev server как production-сервер. Не включайте debug/reload.
Не подключайте демо с неограниченным созданием данных к публичному production.
В текущей работе production-развёртывание и PostgreSQL-прогон не выполнялись.

## Что требуется до публичного запуска

- Проверить миграции и реальные сценарии на выбранной PostgreSQL-версии.
- Ограничить частоту входов, регистрации и запросов на reverse proxy/API gateway.
- Подключить подтверждение email, восстановление пароля и доставку уведомлений.
- Добавить управление сроками хранения, удалением аккаунта и отзывом приглашений.
- Настроить резервное копирование и проверить восстановление.
- Добавить централизованные журналы без cookies, паролей, токенов приглашений
  и содержимого приватных исследований; метрики ошибок и времени ответа.
- Настроить HTTPS, CSP для фронтенда, лимиты тела запроса и процесс обновления зависимостей.

## Состояние среды и публикация

Установленные зависимости и локальная БД сохраняются на диске; живые процессы
после восстановления снимка нужно запускать заново. Сохранённые install/start
инструкции не означают, что конфигурация опубликована или приложение развёрнуто
для внешних пользователей.
