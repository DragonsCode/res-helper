# Проверка redesign · 20 октября 2026

## Среда и реальные прогоны
Локальная управляемая cloud-среда, Python 3.12, Node 24, системный Chromium через
Playwright. FastAPI и React запускались настоящими процессами. Браузерные тесты
используют отдельную SQLite БД и порты 8001/5174; production preview — 4173.
Проверки выполнялись на desktop 1440×1000, tablet 820×1180, mobile 390×844.
Это эмуляция viewport в Chromium, не тест на физических iPhone/Android.

## Покрытие поведения
- Открытое чтение без аккаунта, первоисточники, переход к регистрации.
- Регистрация/вход/выход, профиль, три пользовательских пути с сохранением выбора.
- Создание проекта, задачи, завершение и перезагрузка; материал, закладка и BibTeX;
  обсуждение и ответ. Во всех этих цепочках работает реальная БД.
- Учебный разбор → отметка чтения → библиотека → проект с шестью задачами.
- Паспорт: отложенный ответ и aria-busy, HTTP 503, сохранение ввода, повтор,
  перезагрузка, экспорт Markdown. Backend отдельно проверяет права, tenant isolation,
  ограничения длины и сохранение паспорта при обычном редактировании проекта.
- Несохранённый паспорт: переход по ссылке, browser back, отмена/Escape и дальнейшее
  сохранение без потери текста.
- Карта: количество ячейки совпадает с числом открытых записей, далее доступен
  настоящий инспектор с автором, ссылкой и связью с проектом.
- Диалоги: Enter, Tab, удержание/возврат фокуса, Escape, backdrop и отсутствие
  случайного закрытия при клике на пустое место внутри инспектора.
- Hover/press проверены по изменению реальных computed styles; normal/reduced-motion.
- Network abort чтения пространства и HTTP 503 разбора: ошибка → повтор → данные.
- Пустой поиск и его очистка, пустой аккаунт, раскрытие восьми задач за пределами
  начального списка из шести.
- Мобильное меню открыто/пройдено клавиатурой; каталог, статья и источники доступны.

## Найдено и исправлено
1. Низкая информационная ценность первого экрана: убран рекламный hero из рабочего
   журнала, приоритет отдан реестру, документам и задачам.
2. Маленькие подписи и слабая иерархия: метаданные приведены к читаемым размерам,
   усилены контраст и разделение документа/контролов.
3. Аватары мнимой команды проекта заменены реальным ответственным.
4. После создания проекта кратко показывалось «не найден»: результат API сразу
   добавляется в локальное состояние до перехода, затем синхронизируется.
5. StrictMode/native dialog не всегда фокусировал поиск: теперь после showModal
   выбирается поле ввода, dialog корректно закрывается при cleanup и возвращает фокус.
6. На мобильном скрытый текст лишал поиск accessible name: добавлено постоянное имя.
7. Не было повторов некоторых ошибок чтения; добавлены retry-действия.
8. Пустой аккаунт ошибочно получал сообщение о заполненных паспортах: теперь
   нейтральное объяснение следующего шага. Задачи сверх шести можно раскрыть.
9. Клик по свободному месту внутри высокого инспектора мог его закрыть: закрытие
   по backdrop теперь проверяет границы dialog.
10. Финальная motion-проверка выявила, что универсальный reduced-motion селектор
    не охватывал ::backdrop. Добавлено явное правило и отдельная проверка computed
    animationName для dialog и backdrop; повтор прошёл. Затемнение переведено с
    изменения background-color на opacity, will-change ограничен открытым диалогом.

Один ранний desktop-прогон превысил 180 s во время screenshot в общей cloud-среде.
Лимит большого обхода увеличен до 300 s; повторный desktop-прогон прошёл за 39.5 s.
Это не было скрыто повтором без анализа и не считается доказательством скорости
на пользовательском устройстве.

## Осталось вне проверки и реализации
- Внешние сайты DOI/GBIF/arXiv не проходили end-to-end проверку доступности;
  проверялись href и отображение метаданных источников.
- Нет тестов Safari/Firefox, физических touch-устройств и ручного screen reader аудита.
  Axe не доказывает полное соответствие WCAG.
- Не проводились интервью, usability-сессии и длительный нагрузочный тест.
- Документы без истории версий/конфликтов (last-write-wins); статистического анализа,
  импорта измерений и файлового хранилища нет. Наборы данных представлены ссылками.
- Большие библиотеки требуют серверной пагинации/агрегации; текущие лимиты API
  и ограничения SQLite перечислены в ARCHITECTURE.md.
- Production-готовность, PostgreSQL, восстановление аккаунтов, email, биллинг,
  SSO и LMS остаются отдельными этапами, описанными в OPERATIONS.md.


## Диагностика production-сборки и движения

Chromium **154.0.8037.57**, локальный API, общая cloud-машина, без искусственного
CPU/network throttling. Это небольшие диагностические выборки, не нагрузочный
тест и не performance SLA. FCP — первый контент, не время полной готовности данных.

- Повторный замер рабочего журнала: FCP **588 ms**, CLS **0.049**, idle animations **0**,
  внешние ресурсы **0**, JS errors **0**. На 1440/820/390/320 px: overflow false и
  axe violations `[]`. [Полные значения](runtime-metrics.json).
- Первый замер был значительно медленнее: FCP **11960 ms**, включая long tasks
  до 1074 ms. Он сохранён [отдельно](runtime-metrics-first-run.json), а не исключён
  из результатов. Причину всей вариативности общей машины однозначно не установили.
- Отдельная загрузка landing: FCP **740 ms** без кеша и **440 ms** при повторе;
  timings HTML/JS/CSS/API сохранены в [диагностике](loading-diagnostics.json).
- После изменения backdrop три открытия инспектора дали 9–11 различных положений,
  5–6 уровней прозрачности затемнения и корректное конечное состояние. Медиана
  интервалов rAF 16.7 ms, p95 **49.9–100.1 ms**: стабильные 60 FPS не подтверждены.
  Это выборка computed styles на main thread, не GPU trace; compositor-анимация
  может идти независимо. [Измерения](motion-diagnostics.json).
- В reduced-motion итоговая проверка вернула `animationName: none` для **обоих**
  слоёв; Escape завершает закрытие. Этот случай закреплён в Playwright.

Визуально просмотрены также [инспектор](screenshots/source-inspector-desktop.png)
и [узкий журнал 320 px](screenshots/journal-narrow.png). Таблица прокручивается
локально и имеет пояснение; весь документ не переполняет viewport.

Повторить диагностику после запуска API 8000 и `npm run preview` на 4173:
`node scripts/inspect-runtime.mjs` и `node scripts/inspect-motion.mjs` из frontend.
Скрипты создают отдельную demo-фикстуру; browser-часть не изменяет пользовательские
документы. Реальные UI-мутации покрываются E2E на 5174.
