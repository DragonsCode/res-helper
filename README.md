# Re:Search

**За каждым выводом должен быть источник.**

Re:Search вырос из командного хакатонного проекта в рабочую первую версию платформы
для знакомства с наукой, обучения и совместных исследований. Новый стек —
**FastAPI + React (JavaScript) + SQLAlchemy + Alembic**. Старый Django-проект и его
база сохранены в `legacy/django/`.

## Три пути в одном продукте

| Путь | Для кого | Что уже работает |
| --- | --- | --- |
| Открывать | Интересующиеся люди, журналисты | Чтение без регистрации, разборы с первоисточниками, маршрут проверки научных новостей, личный прогресс и сохранение материалов после входа |
| Учиться | Студенты, преподаватели | Учебные маршруты, создание проекта с готовыми задачами, совместные материалы и обсуждения |
| Исследовать | Исследователи, лаборатории | Реестр и паспорт исследования, карта источников, задачи, библиотека, Markdown/BibTeX, обсуждения и роли |

Путь можно менять в любой момент. Он определяет рекомендации и акценты интерфейса,
а права доступа определяются членством в рабочем пространстве.

Дополнительно реализованы регистрация и вход, серверные сессии, поиск по пространству,
избранное, лента активности, настройки профиля, адаптивный интерфейс и изолированное
демо. Действия сохраняются в базе и проверяются API- и браузерными тестами.

## Запуск

Нужны **Python 3.12+, uv, Node.js 22+ и npm**. Проверенная среда: Python 3.12 и Node.js 24.

Из корня репозитория:

```bash
bash scripts/setup.sh
bash scripts/dev.sh
```

Скрипт установки использует `uv.lock` и `package-lock.json`, применяет миграции и
собирает фронтенд. Скрипт разработки запускает API на порту **8000** и Vite на
**5173**. Откройте порт 5173 в браузере или через доступный в вашей среде механизм
проброса портов. API-документация доступна на `/docs` сервера API, health-check —
`/api/health`.

На первом экране можно читать без регистрации, создать аккаунт или открыть демо.
Каждый запуск демо создаёт отдельную команду с явно демонстрационными данными.
У настоящего аккаунта пространство изначально пустое.

Сервер использует `backend/.data/research.db`. База, виртуальная среда, зависимости
и сборка исключены из Git. Настройки описаны в `backend/.env.example`; если требуется,
создайте свой `backend/.env`, не заменяя существующие настройки.

### Раздельный запуск

```bash
cd backend
uv run uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

```bash
cd frontend
npm run dev
```

Фронтенд обращается к относительному `/api`; Vite проксирует запросы на backend.
Клиент не хранит токены в localStorage. Для ручных изменяющих запросов к API нужен
заголовок `X-Requested-With: ReSearch`.

## Перенос данных из хакатонной версии

После установки:

```bash
cd backend
uv run python -m app.cli import-legacy --source ../legacy/django/db.sqlite3
```

Импорт читает источник только для чтения, выполняется одной транзакцией и повторно
не переносит тот же снимок. Пользователи, публикации, комментарии и положительные
голоса переходят в отдельное пространство «Re:Search · архив хакатона».
Старые PBKDF2-пароли поддерживаются и обновляются до scrypt после успешного входа;
можно входить по прежнему логину. Детали и ограничения — в
[описании миграции](docs/MIGRATION.md).

## Проверки

```bash
cd backend
uv run ruff check app tests migrations
uv run pytest -q
uv run alembic check
```

```bash
cd frontend
npm run build
npm run test:e2e
```

Браузерные тесты сами запускают API на 8001 и Vite на 5174 с отдельной SQLite-базой.
Они используют `/usr/bin/chromium`, если он установлен, либо браузер Playwright.
Для новой машины установите браузер командой `npx playwright install chromium`
или задайте `PLAYWRIGHT_CHROMIUM_EXECUTABLE`. Порты 8001 и 5174 должны быть свободны.

GitHub Actions повторяет проверки API, сборку и браузерные сценарии.

## Структура

```text
backend/
  app/api/              HTTP-контракты и проверки доступа
  app/core/             конфигурация, БД, пароли и сессии
  app/services/         рабочие пространства, каталог, демо и миграция
  app/models.py         модель данных
  app/schemas.py        валидация входных данных
  migrations/           версионируемая схема Alembic
  tests/                проверки поведения API и миграции
frontend/
  src/components/       интерфейс, навигация и формы
  src/pages/            сценарии продукта
  src/design/           семантические токены и motion
  src/context.jsx       сессия и состояние пространства
  src/api.js            единый HTTP-клиент
  tests/                браузерные сценарии Playwright
legacy/django/          исходный проект и база
docs/                   продукт, архитектура, бизнес-модель и эксплуатация
scripts/                воспроизводимая установка и запуск
```

Текущая версия предназначена для локальной работы и пилота. Оплата, email-доставка,
восстановление пароля, институциональный SSO, автоматический импорт публикаций,
оценивание учебных работ и публичная пользовательская лента пока не реализованы.
Каталог содержит редакционную стартовую подборку, а не поток новостей. PostgreSQL
поддерживается драйвером и конфигурацией, но текущий прогон проверок выполнен на SQLite.

### Product identity: Laboratory ledger

Новый интерфейс организован как лабораторный журнал: реестр исследований,
документ вопроса/метода/ограничений, карта связанных материалов и контекстный
инспектор первоисточников. Три уровня аудитории сохранены. Научные выводы не
подменяются процентом выполненных задач или количеством ссылок.
